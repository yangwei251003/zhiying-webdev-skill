# 需求分析与头脑风暴细则

> 阶段一：requirement_analysis 专用参考。用户说"帮我开发职映网站"时加载此文件。

---

## 一、结构化头脑风暴流程（强制执行）

按以下步骤逐项执行，**每个步骤必须达到通过标准才进入下一步骤**。

| # | 步骤 | 通过标准 | 关键追问 |
|---|------|---------|---------|
| 1 | 项目背景调研 | 明确网站类型、目标用户、核心业务场景、竞品分析 | "这个网站的核心价值是什么？为什么用户会选择你的网站而不是竞品？" |
| 2 | 问题清单生成 | 至少包含6个维度的问题，每个维度至少5个具体问题 | "如果只能先实现3个功能，你会选哪3个？为什么？" |
| 3 | 多轮需求确认 | 每轮至少解决5个核心问题，用户明确确认需求方案 | "你确认这个需求方案吗？有没有需要补充或修改的地方？" |
| 4 | 需求文档生成 | 产出完整的需求规格说明书和产品规格说明书 | "需求文档是否符合你的预期？有没有遗漏的功能？" |

## 二、问题清单生成维度（必须包含）

### 2.1 功能需求问题

**必须追问以下问题**：

1. 核心功能是什么？（用户来到网站最主要要做什么）
2. 核心功能的详细流程是什么？（用户如何一步步完成核心功能）
3. 辅助功能有哪些？（除了核心功能，用户还需要哪些功能）
4. 未来扩展功能有哪些？（后续可能要增加的功能）
5. 功能优先级如何排序？（哪些功能必须先实现，哪些可以后续迭代）
6. 每个功能的验收标准是什么？（如何判断功能实现成功）

### 2.2 用户体验问题

**必须追问以下问题**：

1. 目标用户是谁？（年龄、职业、背景、使用场景）
2. 用户旅程是什么？（用户从进入网站到完成目标的完整路径）
3. 用户期望的视觉风格是什么？（现代简约、商务专业、活泼时尚等）
4. 用户期望的交互方式是什么？（点击、滑动、拖拽等）
5. 用户可能遇到的困难是什么？（哪些环节可能让用户困惑）
6. 如何提升用户满意度？（哪些细节能让用户感到惊喜）

### 2.3 技术需求问题

**必须追问以下问题**：

1. 性能要求是什么？（加载速度、响应速度、并发用户数）
2. 兼容性要求是什么？（支持的浏览器、设备、操作系统）
3. 安全要求是什么？（数据安全、用户隐私、防攻击）
4. 可维护性要求是什么？（代码规范、文档要求、更新频率）
5. 技术栈偏好是什么？（是否有特定的技术要求）
6. 部署环境要求是什么？（服务器、域名、SSL证书）

### 2.4 内容需求问题

**必须追问以下问题**：

1. 内容类型有哪些？（文字、图片、视频、音频等）
2. 内容来源是什么？（用户生成、管理员上传、第三方获取）
3. 内容更新频率如何？（实时更新、定期更新、手动更新）
4. 内容展示方式如何？（列表、卡片、详情页等）
5. 内容数量预估如何？（多少条内容、多大的存储空间）
6. 内容管理需求如何？（是否需要后台管理系统）

### 2.5 资源需求问题

**必须追问以下问题**：

1. 已有哪些资源？（logo、IP形象、品牌色、设计风格、图片素材）
2. 需要生成哪些资源？（哪些图片需要AI生成，哪些需要设计师设计）
3. 第三方资源有哪些？（图标库、字体库、组件库、API接口）
4. 资源版权问题如何？（是否需要购买版权、是否可以使用免费资源）
5. 资源更新需求如何？（资源是否会频繁更新）
6. 资源存储方案如何？（本地存储、云存储、CDN加速）

### 2.6 商业需求问题

**必须追问以下问题**：

1. 商业模式是什么？（免费、付费、广告、会员等）
2. 盈利方式是什么？（如何通过网站获得收入）
3. 运营策略是什么？（如何吸引用户、如何留住用户）
4. 市场定位是什么？（目标市场、竞争优势）
5. 成本预算如何？（开发成本、运营成本、维护成本）
6. 时间要求如何？（什么时候必须上线）

## 三、多轮需求确认流程

### 3.1 第一轮确认：核心功能确认

**必须确认以下内容**：
- 核心功能的详细流程
- 核心功能的验收标准
- 核心功能的优先级

**确认话术**：
"我理解你的核心功能是[具体功能]，用户通过[具体流程]来完成，验收标准是[具体标准]。你确认这个理解正确吗？"

### 3.2 第二轮确认：用户体验确认

**必须确认以下内容**：
- 目标用户画像
- 用户旅程设计
- 视觉风格偏好

**确认话术**：
"我理解你的目标用户是[具体用户]，他们通过[具体旅程]完成目标，期望的视觉风格是[具体风格]。你确认这个理解正确吗？"

### 3.3 第三轮确认：技术需求确认

**必须确认以下内容**：
- 性能要求
- 兼容性要求
- 技术栈偏好

**确认话术**：
"我理解你的性能要求是[具体要求]，兼容性要求是[具体要求]，技术栈偏好是[具体偏好]。你确认这个理解正确吗？"

### 3.4 第四轮确认：资源和时间确认

**必须确认以下内容**：
- 已有资源清单
- 需要生成资源清单
- 上线时间要求

**确认话术**：
"我理解你已有[具体资源]，需要生成[具体资源]，期望上线时间是[具体时间]。你确认这个理解正确吗？"

## 四、需求文档生成规范

### 4.1 需求规格说明书（必须包含）

**必须包含以下章节**：

1. **项目背景与目标**：
   - 项目背景说明
   - 项目目标说明
   - 项目价值说明

2. **用户画像与场景分析**：
   - 目标用户画像（年龄、职业、背景、需求）
   - 使用场景分析（何时、何地、为何使用）
   - 用户痛点分析

3. **功能需求清单**：
   - 核心功能（详细描述、流程、验收标准）
   - 辅助功能（详细描述、流程、验收标准）
   - 未来扩展功能（简要描述）

4. **非功能需求**：
   - 性能需求（加载速度、响应速度）
   - 安全需求（数据安全、用户隐私）
   - 兼容性需求（浏览器、设备）
   - 可维护性需求（代码规范、文档）

5. **用户故事与验收标准**：
   - 每个功能的用户故事
   - 每个功能的验收标准

6. **项目约束与假设**：
   - 技术约束
   - 时间约束
   - 资源约束
   - 项目假设

### 4.2 产品规格说明书（必须包含）

**必须包含以下章节**：

1. **产品定位与价值主张**：
   - 产品定位说明
   - 价值主张说明
   - 竞争优势说明

2. **功能模块划分**：
   - 功能模块列表
   - 模块之间的关系
   - 模块优先级

3. **页面结构规划**：
   - 页面列表
   - 页面之间的关系
   - 页面导航结构

4. **交互流程设计**：
   - 核心功能交互流程
   - 辅助功能交互流程
   - 异常流程处理

5. **内容策略规划**：
   - 内容类型规划
   - 内容来源规划
   - 内容更新策略

6. **运营策略建议**：
   - 用户获取策略
   - 用户留存策略
   - 用户转化策略

## 五、强制追问机制

用户回答符合以下任一特征，**禁止接受并进入下一阶段**：

| 特征 | 反例 | 追问话术 |
|------|------|---------|
| 功能描述模糊 | "需要一个展示页面" | "展示什么内容？给谁看？用户看完后要做什么操作？展示的目的是什么？" |
| 用户群体不明确 | "面向普通用户" | "具体是哪类用户？年龄范围？职业背景？使用场景？他们为什么需要这个网站？" |
| 缺少核心场景 | "用户会来浏览内容" | "用户为什么来浏览？浏览后有什么目标？如何判断浏览成功？浏览过程中会遇到什么困难？" |
| 没有优先级 | "所有功能都很重要" | "如果只能先实现3个功能，你会选哪3个？为什么？其他功能什么时候实现？" |
| 资源情况不明 | "需要一些图片" | "你已有哪些图片资源？哪些需要我帮你生成？有没有品牌色或设计风格要求？图片用途是什么？" |
| 时间要求模糊 | "尽快上线" | "具体什么时候必须上线？为什么是这个时间？如果延期会有什么影响？" |

---

## 六、交互风格

1. 像耐心的产品经理，每次只问一个维度的问题
2. 给用户具体示例（"好的回答示例"和"需要补充的回答示例"对比）
3. 用户回答不明确时主动整理成结构化内容，再请用户确认
4. 用户说"不知道怎么描述"时用具体追问引导，不放弃
5. 需求信息不足时绝不假设，必须继续询问
6. 善于总结、提炼核心需求
7. 每轮确认后生成需求文档，请用户审核签字
